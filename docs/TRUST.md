# 可信度边界

这份文档回答一个问题：**这个数据集里的数字，凭什么可以信？**

答案比大多数人预期的要小。写在这里，是为了让别人不必重复踩一遍才能发现。

---

## 一句话结论

**四个来源，一次测量。**

`ahbencat`、`tllandy`、`soschina_wind`（开源证券 / Wind）、`jozhn` 四个来源，
最终都指向同一个上游——上海市网上房地产（fangdi）的网签公示。
它们之间的一致性不是互证，是同一份数据的多次转录。

因此本仓库**不具备独立校验能力**。它能保证的是「我忠实地转录了上游」，
不能保证「上游是对的」。

---

### 为什么「差 0」是警报，不是喜讯

直觉上，多方数据吻合到个位数，应该是可信度极高的证据。在这里恰恰相反。

两次**真正独立**的测量之间必然存在随机误差：抓取时点不同、舍入规则不同、
撤销网签的时滞不同——这些都会造成个位数到百位数级别的漂移。
差 0 说明的不是「两个人都算对了」，而是**「两个人抄的是同一张表」**，或者
「第二条链路上游就是第一条链路」。

唯一那处 **1 套的差异**（2025-06 一手房），反而是整份数据里**唯一一处
真正的独立测量痕迹**——它来自研报图表读数的舍入。

判据写在 `build/independence.py`：

- `identical`（差 0）→ 同源嫌疑，**不计入独立校验**
- `consistent`（差 ≤1%）→ 同量级吻合，弱独立证据
- `divergent`（差 >1%）→ 真分歧，需人工裁定

当 `identical` 占比超过 80%，`verdict` 判为 `single_upstream`，并在
`statement` 里直接写出结论。当前值：**94.7%**。

## 证据二：拿不到一手源

要证明数据对，唯一的办法是越过二手转录，直接读政府公示。实测（2026-10-30）：

| 目标 | 结果 |
|---|---|
| `https://www.fangdi.com.cn/` | **HTTP 412**，返回瑞数动态防护的 `$_ts.nsd` 混淆脚本，非 HTML 内容 |
| `http://www.fangdi.com.cn/` | 连接超时（站点不接受明文 HTTP） |
| `https://sh.lianjia.com/chengjiao/` | **HTTP 302**，重定向至滑块验证页 |
| `https://fgj.sh.gov.cn/` | 200，但为新闻门户，无逐日成交公示 |
| `https://tjj.sh.gov.cn/` | 200，但仅月度房地产开发口径，与网签套数不可比 |

fangdi 的滚动计数器（一手房当日成交）是**实时值，隔日即丢**。这决定了：

1. 任何一次抓取中断都会造成**永久性空洞**，无法事后补；
2. 补齐历史的唯一途径是依赖别人在那一天抓过；
3. 因此所有开源上海网签数据集，本质都是**同一天不同时刻的几次快照**。

绕过瑞数需要执行 JS 生成 cookie，在 CI 里意味着引入无头浏览器——
成本高、极不稳定，且属于规避技术措施，本项目不做。

## 证据三：一手房大部分不是实测

一手房 2025-01 ~ 2026-10 共 22 个月，构成如下：

| 性质 | 月数 | 占比 | 说明 |
|---|---|---|---|
| 每日自动采集（observed / ahbencat） | 1 | 4.5% | 仅 2026-10，27 条日记录 |
| 一次性人工补录（observed / tllandy） | 3 | 13.6% | 2025-06~08，92 条日记录，上游已停更 |
| 研报月度誊录（reference） | 16 | 72.7% | 无日度、无面积、无原始文件 |
| 完全空白 | 2 | 9.1% | 2026-08、2026-09，无任何公开来源 |

也就是说，一手房序列里**真正每天采到的只有 27 天**。
称其为「每日采集的一手房数据」是不成立的；它是一张月度表，
外加两端各一段日度明细。

二手房情况好得多：22 个月中 12 个月为每日自动采集（2025-11 起），
3 个月为 tllandy 一次性补录，7 个月为研报锚点。

**两者质量不同，不要画在同一张日度图里做对比。**

## 这个数据集能保证什么

1. **转录忠实** —— 上游原文归档于 `cache/upstream/`，含 sha256、URL、抓取时刻。
   任何人可以重新取回上游文件并校验哈希是否一致。
2. **内部自洽** —— 月度总量必然等于该月日度求和；`observed` 与 `reference`
   不重叠；`area_m2` 与 `area_quality` 同生同灭。这些由 `validate.py` 阻断式检查。
3. **改版可感知** —— 上游若改表格结构，解析器报 `PARSE_ERROR`，CI 失败而非静默产出空数据。
4. **来源可追溯** —— 每一行都带 `provenance.source_ids`，能追到具体仓库和采集方式。

## 这个数据集不能保证什么

1. **不能保证上游数字正确** —— 网签数据本身有撤销、补录、集中备案等扰动，
   且我们无法独立复核。
2. **不能保证「二手 + 一手」可比** —— 两者口径不同，且质量分布差异巨大。
3. **不能保证及时** —— 依赖 ahbencat 的采集，若其断更，本仓库只能记录陈旧，
   无法自行补齐。
4. **不能保证完整** —— 一手房 2026-08/09 永久缺失。

---

## 如果你要拿它做判断

- 用 `monthly.observed` 看趋势，用 `monthly.reference` 补早期，**不要混算**。
- 看到 `area_quality: "approximate"` 的月份（2025-11 ~ 2026-04 面积是万位取整），
  不要拿它算均价到小数点后两位。
- 一手房的 16 个 `reference` 月份，只能当「量级参考」，不能当日度数据用。
- 任何结论都应该能承受「网签数据本身有 ±5% 扰动」这个前提。
